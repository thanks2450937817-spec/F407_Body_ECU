# F407 Body ECU 项目进度

最后更新：2026-09-11

## 当前工程基础

- MCU：STM32F407VET6。
- CAN1：PB8 接收、PB9 发送，经典 CAN 500 kbit/s。
- 上位机：CANable 2.0 S，CAN 通信已经验证正常。
- 车灯：PA7，低电平点亮。
- 故障注入按键：KEY1/PE3，当前按下按低电平处理。
- 已有 CAN 命令、状态响应、心跳，以及 UDS 0x10、0x3E、0x22 等基础服务。

## 2026-09-11 完成的 DTC 工作

### DTC定义

- 首个模拟故障：`B1000-01`，CAN/UDS中的三个DTC字节为`90 00 01`。
- 当前状态位使用：
  - `testFailed = 0x01`。
  - `confirmedDTC = 0x08`。
- `pendingDTC = 0x04`已经保留定义，但尚未制定和实现状态转换规则。

### 故障注入

- `Fault_injection.c`只读取PE3，不再直接控制PA7。
- 按键按下时开启故障注入：如果目标状态为开灯，PA7被强制为关灯电平。
- 按键松开时关闭故障注入，PA7恢复到CAN命令要求的目标状态。
- 因此只有“目标要求开灯”时，按键才能模拟“灯无法点亮”故障。

### 周期检测与状态更新

- 主循环使用`HAL_GetTick()`每10 ms执行一次灯故障检测，没有新增硬件定时器中断。
- 每次检测只读取一次PA7：
  - 目标电平与实际电平不一致：置位`testFailed`。
  - 两者一致：清除`testFailed`，但不影响已锁存的`confirmedDTC`。
- 使用互不重叠的100样本窗口，100个样本约等于1秒。
- 一个窗口内失败样本达到5次，即失败比例达到5%，置位并锁存`confirmedDTC`。
- `confirmedDTC`在本次上电运行期间不会因后续检测正常而自动清除。

当前可能出现的核心状态：

| 状态值 | 含义 |
|---|---|
| `0x00` | 当前正常，尚未确认故障 |
| `0x01` | 当前检测失败，尚未确认 |
| `0x08` | 当前已经恢复，但故障历史已经确认 |
| `0x09` | 当前检测失败，并且故障已经确认 |

## 当前限制

- DTC只保存在RAM中，MCU复位或掉电后会丢失。
- 尚未实现UDS `0x19`读取DTC和`0x14`清除DTC。
- 尚未实现DTC老化、运行周期和Flash/NVM持久化。
- 当前是按键故障注入，并不是真正的LED开路、电流或电压反馈检测。
- 100样本采用独立窗口，存在窗口边界效应；当前教学阶段先接受，后续可改成滚动窗口。
- PE3当前CubeMX配置为`GPIO_NOPULL`，需要确认开发板按键具有外部上拉；否则后续改成内部上拉。
- 按键尚未单独加入软件消抖。
- 编译仍有两个此前就存在的`can_app.c`未使用局部变量警告，与本次DTC逻辑无关。

## 下次继续位置
